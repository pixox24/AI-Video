## 修复内容

| 问题 | 本次实现 | 主要位置 |
|---|---|---|
| G01 请求校验与旧结果覆盖 | 客户端 requestId 原样穿过路由与领域服务。接收只接受当前请求和一致来源，不再用结果版本变化拒绝合法重编。写稿、诊断和重编从发起时建立操作标识，在接收、后续处理、最终提交处检查最新工作区；切项目重新挂载、卸载撤销旧操作。被废弃的结果不会提交旧 base 或显示重编完成。 | `server.ts`、`ScriptPanel.tsx`、`visualBibleService.ts`、`visualBibleAsync.ts` |

| G03 显示名影响实体识别 | 上镜识别同时查询台账规范名和显示名，保持相同 entityId；英文使用词边界。对白归属也补充规范名匹配。 | `visualBible.ts` |
| G04 迟到参考图覆盖或串人 | 生成和上传均捕获项目 ID、实体 ID、来源、目标状态版本及原卡对象；完成时核对最新目标。禁止按 cardId 回退匹配。目标发生编辑、换图、清图、删除、替换或切项目时，旧图不写回。生成请求按目标保留最新请求标识，上传请求也检查当前任务。 | `visualBibleAsync.ts`、`App.tsx`、`ScriptPanel.tsx` |
| G05 缓存绕过版本 | 路由传递实际模型与语言。sourceKey 和 analysisCacheKey 来自统一规范化输入。内存缓存和 previousBible 恢复都核完整缓存键；持久化完整分析快照，不再用空 entities 假装恢复完整分析。失败明确降级、不缓存成功；同输入并发分析合并，强制分析可绕过缓存。 | `visualBibleService.ts`、`visualBibleSource.ts`、`types.ts` |
| G06 编卡遗漏风格 | 正式编卡请求恢复风格世界、服装、空间、渲染约束，加入完整输出 JSON 契约、证据归属、未知事实、实体/实物区分和 refs/locked 规则。模型仅能提供设计字段，不能作为用户锁、override 或台账的来源。 | `visualBibleService.ts` |
| G07 代词性别冲突 | 性别冲突的候选被排除，并继续向前查找合法主体。多个无法区分的单数候选不强行绑定为多人；未找到合法主体时不回退到明确相反性别的人物。 | `visualBible.ts` |

另修复一个关联路径：pinned 快照在换稿请求时保持完整来源和事实，不调用模型重新编译；用户显式选择重编后才解除该冻结状态。

## 数据兼容与状态行为

新增的可选字段：

- `VisualBible.analysisInput`：规范化分析输入，包含语言。
- `VisualBible.analysisSnapshot`：用于完整恢复的分析结果；仍经过领域台账校验和投影。
- `ScriptEntityRecord.analysisStatus`：应用用户决定之前的基础状态。
- `EntityUserOverride.decisionCard`：排除/恢复操作所需的卡片与资产。

旧数据没有有效版本化分析快照时会重新分析，而不是错误地认为缓存有效。旧 include/exclude 台账在加载时可从原文和分析信息恢复基础状态。新字段均兼容缺省值，没有一次性批量重写用户项目。

`decisionCard` 参与持久化和资产保护，但不把完整历史卡片/缩略图纳入提示词版本哈希，避免隐藏资产让版本计算变大。重新纳入角色后，活动卡的实际约束照常参与版本计算。

参考图请求标识只保存在运行时，不写入用户项目。工作区或目标已改变时采用保守丢弃：用户可以在新状态下重新生成，旧结果不会自动覆盖新设置。

测试集有重叠，不能把各命令通过数量相加当成独立场景数。三轮审计独立计数共 35 项。

新增 [工作流测试](../src/utils/visualBible.workflow.test.ts) 重点验证：

1. 当前请求允许结果版本改变，旧请求和语言不一致的响应被拒绝。
2. 工作区改稿、改锁、后发请求及卸载使旧操作失效。
3. 四个外形字段分别编辑和主动清空，JSON 保存/加载后其他字段保持。
4. 改显示名后，原文点名和后续代词仍引用同一实体。
5. 有效参考图正常写入；项目、来源、实体或用户编辑变化时拒绝旧图。
6. 原图生成中用户上传后又清除，虽然最终外观回到原状态，旧请求也不得写回。
7. 完整分析快照保存后清空内存缓存仍可恢复；换模型和强制分析会重跑。
8. 分析异常明确降级，随后可成功重试；同输入并发只分析一次，实体快照不丢失。
9. 英文语言、CRLF 和重复粘贴规范化一致。
10. include/exclude/auto 多轮切换和重载保持基础事实，旧工程可恢复自动。
11. 排除角色的参考图仍受资产引用保护，恢复后能找回。
12. pinned 换稿保持事实和来源，不触发编卡。

第三轮审计仍执行生产路由和真实参考图 updater。由于 updater 新增了请求上下文，审计只增加对应运行时绑定；S01–S11 的业务断言均保留，没有放宽“旧图不能覆盖新图”和“不能按重用卡 ID 串人”的要求。

## 后续验收边界

本轮验证是本地确定性测试、模拟模型的真实路由函数测试，以及真实 updater 的执行测试，不是浏览器完整点击和真实付费模型质量评测。

原优化方案的全部 T01–T32 能力、复杂共指图、手动 occupancy 持久化、多参考图供应商行为及容量策略，仍应按原方案逐项独立验收，不能因为本轮 G01–G08 修复就视为全部完成。100 篇标注文案及 20 个完整项目抽检仍需执行，届时才有依据评估真实效果是否达到 9.5 分。
