## 已复现问题与修复要求

### 1. P1：刚生成就被判定过期，分析缓存也无法命中

输入“我走进房间，然后我看向窗外。”，体裁“情绪”，标题“独白”。当前真实路由返回的 sourceFingerprint 使用原始候选 ID；客户端检查却使用最终台账 ID。台账增加了第一人称讲述者后，文案未变也得到 `stale=true`。App 随即拦截生图，重复重编也不能解决。示例两端指纹为 `7b44058789690514` 与 `ecaadb1e8e10ac39`。

缓存同时把带 genre/mode 的路由指纹与不带它们的台账指纹比较。即使完整传回已钉住的前一版本，相同输入仍再次调用分析和圣经生成，共 2 次。

位置：server.ts:1959、1975、2042；src/utils/scriptEntity.ts:431；src/utils/visualBible.ts:100。

修复：将“分析输入指纹”和“编译结果版本”分开。输入指纹仅由统一规范化后的原始输入、分析规则版本决定，服务端、客户端、缓存共用同一函数和同一字段集合；结果实体 ID 不应倒灌成输入指纹。缓存完整分析结果，不依赖是否锁了角色卡。

验收：普通、匿名、第一人称、LLM 补充实体等情况，刚生成均不误报过期；相同输入不重跑分析；修改实际依赖后正确失效。

### 2. P1：用户确认或拒绝匿名角色，紧接着被自动校验撤销

输入“一个女孩走进房间，她拿起书本。”。“确认为角色”先将卡改成 confirmed，但没有同步实体台账。UI 的 patchBible 随即调用 groundVisualBible，重建台账又把它改为 pending。点击“不建卡”也只修改 pendingCharacters/rejectedCast，后续 fallback 再次创建同一待确认卡。

位置：src/utils/visualBible.ts:1812、1828、850、919；src/components/ScriptPanel.tsx:2446、2627、2634。

修复：将确认/拒绝记为实体级用户决策，例如 `userDecision=include|exclude|auto`，按稳定 entityId 保存。ground、fallback、重编、工程加载都必须读取该决定；确认时同步状态和来源，拒绝时记录排除项，不能只改展示数组。

验收：点击后立即有效；改外形、切换阶段、重编、保存再打开均保持决定；明确取消用户决定后才恢复自动分析。

### 3. P1：服务端“不建角色”的分析结论在前端被改回

输入“王小明说：‘看这里，这是细胞分裂的三个阶段。’”（复现脚本使用中文双引号），体裁选“故事”，分析确定为 science_explainer、置信度 0.95。服务端正确返回 characters=[]；前端收到 analysisApplied=true 后虽传入空 candidates，groundVisualBible 仍合并 bible.candidates，重建没有 contentType/analysis 的台账，再依据“故事”体裁补回王小明。

位置：src/components/ScriptPanel.tsx:524；src/utils/visualBible.ts:850、940；src/utils/castStrategy.ts:94。

修复：服务端输出已验证的完整台账与决策版本；前端只做结构校验及展示，或以纯函数方式使用同一份完整分析。禁止把已验证台账反转成简化 candidates 后再次推断。工程加载也采用同一规则。

验收：API、前端、工程保存重载后的角色 ID、状态、presentation、判定理由保持一致；体裁不能覆盖高置信分析事实。

### 4. P1：真实证据可以被借给不存在的角色

原文只有“王小明走进教室。”，LLM 实体为“李小红”，evidence 却引用“王小明走进教室。”。目前子串验证通过，toRecordFromAnalysis 把“有任意原文证据”当作“该实体出现在原文”，最终可得到王小明、李小红两张硬角色卡且 warnings=[]。

位置：src/utils/scriptAnalysis.ts:159；src/utils/scriptEntity.ts:281；src/utils/visualBible.ts:824。

修复：同时验证证据存在和证据支持该实体。具名实体必须存在准确 mention；别名、代词需要可追溯的共指链接，不能用整句存在代替实体出现。校验每个实体，不能以“至少有一张卡匹配原文”放行整组。

验收：伪造句子、真实句子配错误人名、同名不同人、别名和代词分别覆盖；无依据实体不得进入 confirmed。

### 5. P1：外形锁仍可能从旧角色串到新角色

上一版王小明和下一版李小红恰好都使用 char-lead，王小明开启外形锁。mergeVisualBible 按卡 ID 优先匹配，得到“李小红 + 王小明的旧外形 + 李小红的 entityId”，后续校验没有报警。卡数组内部 ID 唯一并不能证明跨版本身份相同。

位置：src/utils/visualBible.ts:1194、1134。

修复：跨版本合并必须按稳定实体身份匹配，禁止仅因展示卡 ID 相同就携带外形/参考图。新实体与旧实体 ID 复用时明确分离，保留旧用户资产为独立条目。

验收：角色换名、换稿、顺序变化、复用 char-lead 时，脸、衣服、参考图均不串人；同一实体跨版本能保持用户指定字段。

### 6. P1：三种锁只在开关层独立，重编时仍互相影响

身份锁开启、已有参考图、refsLocked=false。重编后 carryCharacter 用 `previous.locked && previous.refs.length` 将 refsLocked 重新推为 true，旧图被保留。用户明确解开的参考图锁失效。

位置：src/utils/visualBible.ts:1138。现有“三把锁互相独立”测试仅检查 toggle 结果，未经过 merge/rebuild。

修复：只对缺少新字段的旧数据做一次迁移；新数据明确的 false 必须保留，不能用聚合 locked 字段覆盖它。锁迁移增加 schemaVersion。

验收：三种锁 8 种组合均经过 normalize、merge、ground、保存重载；逐字段核对保留/更新行为。

### 7. P1：连续动作改用代词后，主角从上镜计划消失

三镜“王小明走进教室。”“他拿起课本。”“随后他坐下读书。”，当前上镜计划为 true/false/false。函数虽接收完整 shots，却没有利用前文解析后两镜的“他”。这不是需要强行出镜的环境镜，而是明确的人物动作。

位置：src/utils/visualBible.ts:1275、1298、1350。

修复：在实体分析阶段输出每句 mention/共指/动作主体，occupancy 读取这一结果。保留合理的无人 insert；不要通过全局默认主角补回。对照镜也不能仅因存在 support 就自动换成配角。

验收：具名→代词、两人同行、对话换人、省略主语、环境镜、物件镜均验证正确人物集合；人物动作不能因未重复姓名而丢角色。

### 8. P1：subjects 拆分后没有继承角色的证据校验

口播只描述咖啡和水杯，输入一个 entityId=missing、证据不存在的“虚构产品”。groundVisualBible 原样保留这个 subject 且 warnings=[]。目前只对 subjects 去重，没有验证它对应哪个实体和证据。

位置：src/utils/visualBible.ts:858、935、1600。

修复：characters 和 subjects 共用实体与证据校验器；分别约束允许的类型，未知或不匹配的实体引用拒绝进入硬约束。重编时清除失效的未锁实物，锁定实物保留并明确提示来源变化。

验收：实物伪造、错 ID、类型错误、旧稿实物残留都能发现；未验证实物不能进入最终 OBJECT LOCK。
